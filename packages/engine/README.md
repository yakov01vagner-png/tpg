# @tpg/engine

Ядро симуляции. Всё игровое состояние и все правила живут здесь.

## Правила пакета

1. **Никаких импортов React, React Native и платформенных API.** Пакет обязан
   одинаково работать в приложении и в Node — на этом держится возможность
   вынести мир на сервер (DESIGN.md, п.2).
2. **Состояние — сериализуемые данные.** В `GameState` нет функций, классов и
   ссылок на UI: его можно целиком положить в JSON и поднять обратно.
3. **Менять состояние можно только командой.** `applyCommand(state, command)`
   возвращает новое состояние и список событий; исходное состояние не меняется
   (на это есть тест).
4. **Случайность детерминирована.** Генератор передаётся в состоянии; из одного
   сейва одна и та же команда даёт один и тот же результат.
5. **Текст для игрока формируется из событий** (`describeEvent`), UI ничего не
   досочиняет.

## Что внутри

| Файл | О чём |
|---|---|
| `time.ts` | Игровые часы: время двигают действия, тикающих часов нет |
| `attributes.ts`, `skills.ts` | Шесть атрибутов и привязанные к ним навыки |
| `progression.ts` | Кривые роста, мягкий потолок от атрибута, уровни персонажа |
| `magic.ts` | Лестница рангов: навык даёт право, признание даёт ранг |
| `character.ts` | Персонаж, усталость, теги биографии |
| `content/` | Данные: работы, наставники, испытания |
| `commands.ts` | Команды и их правила — единственная точка изменения мира |
| `save.ts` | Сериализация и миграции сейвов |

## Команды

```
npm test         # прогон тестов
npm run typecheck
```

`test/balance.test.ts` не проверяет корректность, а меряет темп: за сколько
игровых дней персонаж доходит до ранга Адепта. Если правка констант ломает
темп, тест это покажет.
