# TPG — правила репозитория

Мобильная текстовая RPG-песочница. Дизайн — `DESIGN.md`, текущий план работ —
`PLAN.md`. Оба файла живые: решения записываются туда по ходу обсуждения.

## Структура

```
packages/engine   ядро симуляции (чистый TypeScript)
apps/mobile       приложение на Expo (появится на этапе 2)
```

## Правила, которые нельзя нарушать

1. **В `packages/engine` нет импортов React, React Native и платформенных API.**
   Ядро обязано запускаться в Node: на этом держится возможность вынести мир на
   сервер (DESIGN.md, п.2). Нарушение этого правила стоит переписывания ядра.
2. **Состояние меняется только командой.** `applyCommand(state, command)`
   возвращает новое состояние и события. UI не мутирует состояние и ничего не
   досчитывает сам — он отправляет команду и рисует то, что вернулось.
3. **`GameState` — сериализуемые данные.** Никаких функций, классов, ссылок на
   UI: состояние целиком кладётся в JSON и поднимается обратно.
4. **Случайность живёт в состоянии.** Генератор передаётся явно; из одного сейва
   одна и та же команда обязана давать один и тот же результат.
5. **Меняешь форму `GameState` — поднимай `SCHEMA_VERSION` и пиши миграцию** в
   `packages/engine/src/save.ts`.
6. **Контент — данные, а не код.** Работы, наставники, испытания, биография
   лежат в `content/` и описываются структурами; логика их только читает.

## Команды

```
npm test         прогон тестов (vitest)
npm run typecheck
npm run lint     biome: форматирование и линт
npm run format   то же самое с автоисправлением
```

Перед коммитом должны проходить все три: `lint`, `typecheck`, `test`.

## Тесты

Правила проверяются в ядре — там это дёшево. UI тестами не покрываем.
`packages/engine/test/balance.test.ts` меряет темп прогрессии: если правка
констант ломает баланс, тест покажет это числом.

## Язык

Код, идентификаторы и коммиты — английский. Комментарии, тексты для игрока и
документы — русский.
